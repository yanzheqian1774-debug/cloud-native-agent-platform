# 执行步骤编辑 R3：字段映射与实施评审

评审结论：画布、就地属性编辑、插入步骤及现有保存/验证/发布交互可进入实现；不能把示意输入来源当成已有执行数据绑定。R3 是视觉参考，不是生产功能。F3 企业流程架构、业务活动及能力关联保持独立。

| R3 项目 | 当前契约 | 呈现与实施判断 |
|---|---|---|
| 步骤名 | WorkflowTask.name；taskId 自动稳定生成 | 可编辑，必填；内部标识折叠。 |
| 技能与操作 | skillOperationBindings[] 的 skillId/skillRevisionId/skillDigest/operation；references[] 保留对应精确技能 | 正式目录按名称选择；不从名称猜操作；唯一明确选项可带入，多个需选择。已有多绑定不得静默丢失。 |
| 输入引用 | WorkflowTask.inputs: string[]；WorkflowContent.inputs: string[] | 当前只有输入名称声明，没有 sourceTaskId/outputKey 或类型兼容契约。不得宣称已实现上一步产物自动传递，也不能把自由文本解析成执行事实。先保留可编辑声明；真实来源绑定单列后端缺口。 |
| 输出定义 | WorkflowTask.outputs: string[]；WorkflowContent.outputs: string[] | 名称声明可编辑；不等于实际产物或已核实的操作输出模式。已有内容带入，缺少必需业务说明才补齐。 |
| 开始条件 | dependsOn: string[] | 仅前置步骤完成依赖；按名称选择并显示画布连线。不新增条件判断/循环/并行语义。依赖不是输入绑定。 |
| 运行设置 | retryLimit、timeoutSeconds、failurePolicy；方案 runtimeProfile 精确引用 | 已知值自动带入，默认折叠；新方案没有真实默认环境时必须选择。保留 capabilityRequirements 与其他 references，不隐藏丢弃。 |
| 方案信息 | definition.name；content.description/inputs/outputs/runtimeProfile | 已保存名称按现有契约不可改；新建可填。业务流程/责任不是这些字段的别名，不新造领域字段。 |
| 保存/验证/发布 | /api/workbench/v1/workflows/commands：create/edit/validate/review/publish/successor；GET commands/{key} 与 authoring | 复用原提交键、版本、digest及回执。保存不执行；改动后重新保存验证。保留现有复核，不新增逐步审批。 |

## 可实施范围

替换大卡片长表单为紧凑横向画布与右栏；选中节点就地编辑；连线上插入真实新任务，稳定生成ID并检查依赖环、下游引用与删除影响；用户输入直接保存在整份草稿中，不增加每步保存。画布位置与缩放仅视图状态，不改变执行关系。保存失败/验证失败保留草稿；未知提交先核对原回执，禁止新建重复命令。

画布需支持现有多依赖图，不能把所有任务强制变成线性链；视觉按依赖层次排列。未保存内容、选中节点、视口、右栏滚动按身份与方案隔离保留；版本切换不得把旧草稿覆盖到新版本。

## 未支持或必须如实处理

1. 输入来源强类型绑定及兼容性推断：无持久契约，不能仅靠下拉框假装实现。与评审会话反馈，先实现其余可支持范围。
2. 后端验证当前主要返回 reasonCode，缺少标准节点/字段路径。可将真实本地结构检查定位到字段；不能把全局后端错误任意归到某节点。结构化诊断可作为独立内部API增量，需另列实现与测试。
3. 示例“收到本次工作资料后”、示例候选操作和示例验证通过不得硬编码成事实。

## 验收

按R3同尺寸对照；实际新增、改输入声明/依赖、保存、验证、复核发布、刷新、详情返回；记录每项通过/未通过/未测。检查未保存输入、选中节点、视口和右栏滚动。无模型或业务任务启动。当前本报告为实施评审，不是已实现或页面验收。

代码依据：console/frontend/src/api/workflowDefinitions.ts；console/backend/src/agent_console/workflow_definition_schemas.py；workflow_definition_service.py；workbench_workflow_authoring.py。
