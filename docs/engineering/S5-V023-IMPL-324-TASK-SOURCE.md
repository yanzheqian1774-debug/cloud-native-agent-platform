### 4.1 执行契约

复用现有 execution、governed execution、Native、Skill invocation、权限、预算、Evidence 和 Outcome owner，不建立平行执行器或新账本。

在编码前固化：根 Assignment 与 Task Assignment 责任、Definition→Instance→Assignment 精确引用、单 Run 唯一性、Task 输入输出、静态 DAG 验证、最大规模与超限拒绝、失败传播、skip、terminal、取消和 UNKNOWN 状态表。禁止动态增图、循环或跨 Runtime 状态迁移混入本批。规模限制至少覆盖当前六任务，具体有限值经仓库契约登记，不能静默保留五任务上限。

每个 Task 映射到经 owner 校验的 typed operation、精确 Skill/MCP/知识/数字员工资源及 I/O。映射快照须可审计、可失效、在派发前重核。不能依据 Plan 自然语言直接自由调用工具。已有 Workflow 是可复用形式，不要求额外制作 Workflow 才能演示。

### 4.2 资源准备与数据

资源状态区分 MISSING、UNREADABLE、UNKNOWN、UNAVAILABLE，不向无权用户泄露不可读资源详情。候选按能力和条件匹配，展示简明理由及缺口。选择权限内已有资源；没有资源时形成建设待办，不假冒已发布资源。

合成数据需覆盖月份、项目归属、预算、Token 用量、账单与分摊依据，并保留明确缺失／异常样本。不得为所有标准构造必通过数据。通过正式只读资源入口提供，来源文件与清单、摘要可核验。运行记录和产物写入平台属于必要持久化，不代表允许修改来源业务数据。

模型如参与分析，绑定明确用途和配置，延续有效开发授权及真实计量；资源读取与模型调用各自遵守既有准入。费用不得成为反复审批同一测试的理由；也不得伪造零价、释放旧 UNKNOWN 或复制账本来避开规则。

### 4.3 结果与标准

终态 Run 形成 Evidence snapshot，再评价原 Criteria。对每项显示“符合／不符合／不可评估”及证据、生成时间、版本。模型建议和可计算检验不能代替 Human 结果决定。拒绝、补充和分歧追加保留，不覆盖历史。

演示允许形成“部分可评估、需要补充资料”的结果；这可以证明验收机制运转，但不得宣称业务目标全部达成。只输出数据缺口报告时，明确成本归因与收益结论尚未获得证明。
