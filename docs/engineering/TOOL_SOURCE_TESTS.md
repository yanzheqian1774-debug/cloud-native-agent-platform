## Exact-source validation and publication

A current exact binding plus Tool-owned committed claim/result can resolve only PLUGIN_RUNTIME_VALIDATION_REQUIRED. The lifecycle callback rereads actual, original test input, exact Tool/revision/source/entry/runtime and invocation digest, observation and actual digest, then validates the current input/output contract. Terminal status eligibility is checked explicitly: UNKNOWN and NOT_EXECUTED are always rejected; FAILED is eligible only for an expectation mismatch and still needs the exact actual/proof/contracts. A PASSED comparison alone or user expected output never confers validation. No actual, malformed proof, UNKNOWN, stale revision/source, changed runtime, expired binding or revoked current Tool READ/TEST cannot provide this evidence. Other import blockers remain blocking.

VALIDATE and PUBLISH retain their own independent original Tool authority and owner transaction. PUBLISH also requires prior exact VALIDATE and rechecks current runtime evidence; TEST never grants PUBLISH. No source/revision bytes or historical issues are rewritten. Read APIs expose sourceValidation/effectiveBlockingIssues as derived exact validation facts; currentAuthorizationChecked=false and executionAuthorized=false distinguish past source validation from a current invocation grant. The existing strict published-member/candidate owner is unchanged. Current published detail is no longer mislabeled historical merely because no draft exists.

This verifies only the reviewed finite synthetic entry code. The HTTP client's timeout/deadline can reject late output; it is not proof that runtime source code was physically terminated. No runtime or server executor changes are included in this increment. Production deployment still requires independently verified server-side task/process hard termination and input/output/resource limits. The local known finite script fixture, definition validation and publication do not establish arbitrary code safety, a production runtime installation, business Native execution or enterprise acceptance.
