# Owned conversation understanding admission

G1 isolated successor adapter. Existing v3-execution model already supports ANSWER
and DIRECT_ANSWER for greetings/explanations; no model registration or prompt change.
The incident was an exact two-conversation admission limit followed by a denied
READ masking the original binding error. Never replay that incident automatically.

Explicit experience v3 declares ownedConversationUnderstanding and pins the exact
predecessor v1/v2 digest. The unchanged predecessor projection keeps old task
admissions valid. New own unarchived conversations gain understanding only, with
current DB owner/message verification, the same subject/account/limits/allowance,
and a separate v3 policy digest in new records and grant audit. No new ledger,
window, source, business execution or other user is admitted. Exact work/plan gates
retain their old conversation list. Removing this declaration closes new general
admissions without rewriting historical contexts.

Preflight precedes draft claim. The UI retains a known admission refusal and does
not poll it into NOT_FOUND or resend it; unclassified understanding has a light
status rather than a five-step execution plan. Complex task state stays unchanged.
Root performs policy publication/deployment and live verification.

## Operator migration (not performed by this change)

Read the current local v1/v2 configuration; do not regenerate its allowance or
limits. Create a separate private successor file containing the exact existing
fields plus schemaVersion=f3-conversation-experience.v3,
ownedConversationUnderstanding=true, predecessorSchemaVersion=the original
schema, predecessorPolicyDigest=the existing adapter policy_digest. The adapter
recomputes the predecessor digest and rejects any changed original field. The
new understanding_policy_digest identifies only the additional own-chat scope.
Existing v2 allowanceId, configuration, cumulative reservations and expiry remain
unchanged. Do not mutate the old file or invoke a fresh budget preparation.

Activating this file is a separate operator step. Old exact business contexts
retain the predecessor digest. New general contexts are checked against the v3
digest plus current conversation ownership/archival and exact original message.
Source, work and planning policies are not expanded. No HUMAN_REVIEWED facts or
model candidate configuration are changed by this package.

## Acceptance boundaries

The isolated tests use real PostgreSQL owners and controlled understanding
results, not real model responses. Browser tests use controlled API routes.
They demonstrate ordinary-question presentation, preserved refusal and no task
writes; they do not prove real model quality or runtime publication.

The existing business-chat composer cannot safely use Journey.answer for an
unrelated question: that changes the task phase. A separately scoped read-only
question channel is the next atomic portion of this same delivery. Until that
portion is verified, the combined A/B/C acceptance is incomplete. Existing task
and UNKNOWN records must never be reset to make ordinary chat appear successful.
