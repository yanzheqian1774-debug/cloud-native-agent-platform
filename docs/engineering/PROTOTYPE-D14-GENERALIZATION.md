# D14: evidence-bounded question generalization (G1)

User scope: assess solvability, derive completion criteria from the question and
available evidence, adapt data and tools, demonstrate a new non-sales question
inside the original conversation. This is not universal autonomous capability
creation or production acceptance.

## Implementation

Introduce an internal, bounded declarative tabular diagnostic adapter. Column
names, grouping dimensions, units and threshold definitions belong to the exact
published source, not to a named business scenario. No generated Python/SQL,
network writes, new database, CRD, lifecycle, or public frozen contract changes.
Preserve existing sales and delivery adapters and all historical records.

Discover published synthetic sources by supported adapter. Report structural
data gaps and observed compatible operations separately from authorization and
runtime readiness. Derive source-bound, question-specific criteria; never use a
sales rubric for other questions. Preserve human business acceptance.

Use existing resource publication, immutable revisions, employee assembly,
planning, policy confirmation and native worker owners. Register the adapter in
both preparation and native registries. Reject unsupported expressions, missing
fields, conflicting units and operations without compatible published tools.

## Validation and acceptance

Unit tests: two unrelated tabular domains with different column names; missing
columns, invalid numbers, duplicate row IDs, unsupported operations; exact source
lineage and independent recomputation. Regress existing source and task bindings.
Frontend lint/build and conversation tests. Then publish synthetic test assets
through existing owners and run a new non-sales question in the real conversation
using real understanding/planning and native execution. Capture video, source
rows, criteria, result and independently recomputed evidence. Do not claim live
acceptance until that run finishes. Known gaps and unsuccessful runs retained.

Risks: schema support is not natural-language goal coverage; declared thresholds
are source facts, not inferred business policy; execution success is not business
resolution. Unknown requests must not be replayed. Exact source/role checks and
existing budgets remain mandatory. No ordinary user's grants are broadened.
