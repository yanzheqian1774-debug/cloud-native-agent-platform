## Evidence semantics and release preparation
`profileDigest` is the registered Model connection-profile digest, NOT the draft-understanding profile digest. `adapterDigest` is the registered adapter-policy canonical digest (policy_for result); `schemaDigest` is the canonical response-schema digest. The typed successor may introduce an exact provider revision for a new adapter contract while retaining the logical provider, endpoint destination, native model and explicit predecessor. These are compared with real persisted Model records; no arbitrary provider destination is enabled.

`codeVerification` pins an independently generated offline verification report. It must contain PASS_OFFLINE_ONLY, exact modelDigest/connectionProfileDigest/adapterPolicyDigest/schemaDigest/provider, standingAuthorizationDigest/sourcePolicyDigest, sameOriginalBudget=true, modelCalled=false and nonempty sourceFiles (absolute paths and raw SHA256). The report is not generated by the Model owner or a model. The release operator must produce it by importing policy_for/_profile from the FINAL installed candidate, comparing actual schema/instructions/profile to frozen candidate inputs and recording all relevant source bytes (including the verifier script). The existing root offline-release-configuration-check.json is supporting evidence, not directly sufficient without these exact additional bindings. The root's standing-authorization record stays pinned alongside its bounded successor disposition; no individual human-review fact is asserted.

The owner rereads every source-file pin, report pin, standing/source perimeter pin and schemaArtifact JSON before and immediately before atomic publication. `schemaArtifact` raw SHA256 is pinned and its canonical digest must match schemaDigest. The immutable decision stores the report and schema artifact digests plus complete policy snapshot. This verifies that the trusted operator's exact independently verified material has not changed; it does NOT re-execute arbitrary verifier scripts, magically prove arbitrary code semantics, or treat a self-authored report as authority. The private policy (absolute, same UID, 0600, no final symlink) is the deployment trust boundary, like other explicit policy files. Root alone creates/enables it after final installed-source verification.
