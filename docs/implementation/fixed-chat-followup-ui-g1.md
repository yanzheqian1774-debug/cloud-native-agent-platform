# Fixed-chat result follow-up UI — G1 successor

This separate successor builds on the frozen fixed-chat activity package. It does not modify that package's evidence, the original fixed target, or the old manual PLAN pause. The backend focus owner is a separate dependency; enabling the existing C1 capability alone does not enable this path. `capabilities.fixedWorkFollowup` defaults false.

A selected, exactly read EXECUTION event supplies only candidate identity references. An explicit user send first reads the current conversation version, records a local intent, and calls the backend focus owner. Its receipt must match conversation, command, binding, work, event, receipt, preparation and run, with a real link ID, digest and content-coverage fields. The original message owner then saves the real focus link. The original C1 route consumes that saved message; frontend run references do not authorize model context, execution or answers.

The UI preserves an unresolved focus command and only GETs its receipt. A later RECORDED observation permits an explicit continuation of the same unsent message; NOT_RECORDED after response loss never automatically POSTs again. A message intent is marked sent before its POST; response loss uses its original message key for readback. The old model owner owns reservations, settlement and model idempotency. Refresh invokes neither model nor START. Current session/scope/CSRF checks and session-expiration fencing stop a stale continuation; durable fixed-mode request storage does not include session expiry.

Fixed mode excludes old CURRENT_QUESTION adoption and failed-understanding retry discovery and checks the mode again at apply/dispatch boundaries. It never borrows service ANSWER/START permissions. A C1 request associated with a fixed focus may produce direct answers or clarification; an execution answer is not applied. Independent new-goal adoption and changes to fixed arrangements are not implemented by this slice. Those require their existing or explicit successor goal/difference-confirmation owners; no journal is overwritten here.

A fixed focus link is projected with target=null and a bounded fixedCycle identity. Returning from its message selects the exact event; mismatches or undiscovered historical events are not replaced with another run. Generic Human work links retain their original behavior and are not fabricated for service runs. The input and normal cycle reader are retained.

When the backend supplies only result excerpts, the request notice and readable message association explicitly state that the complete body was not included. The server remains responsible for current basis READ checks on dispatch, retention and history. The UI consumes only the safe link projection, not internal grants or artifact contents as authority.

Validation is controlled browser protocol testing plus TypeScript/lint/build; it is not an actual model, natural-cycle, deployment or permission acceptance. Backend owner PG evidence remains separate. The original fixed-chat activity package and compatibility contract patch retain their own hashes. The later combined normal checks and actual acceptance are root-owned.
