## Candidate implementation checkpoint

Production modules now provide exact caller-transaction instance/assignment/
runtime binding, a separate disabled-by-default explicit read-only work policy,
and one fixed-source-Plan continuation command plus read-only recovery. The
command independently grants exact instance/assignment/Run/participant/Skill/
evaluation/read permissions through the existing real policy issuer, creates a
truthful policy execution-preparation successor (no invented model invocation),
confirms its exact mapping, prepares the canonical candidate and queues one Run.
All stages commit with one immutable existing-owner command receipt; a permission
or validation failure rolls back instances, Plan and queue writes together.

The existing Native owner has an optional atomic eligible-dispatch filter with
unchanged default behavior. Ready discovery filters the same exact dispatches
before its scan limit. A Native-only entry hosts the standard Operator work loop,
not an acceptance script. Only its own admitted receipt set is claimable; it never
turns UNKNOWN/retry-wait into work. One shared registered-readonly executor
registry supports existing supplier/sales/cost adapters; continuation policy
supports only independently scoped supplier/sales and a single attempt. Terminal
evaluation uses the existing evaluator and original saved actor/current grants;
Human business outcome confirmation is never granted or written automatically.

The business page starts continuation only after actual READY resource receipt
and explicit server capability. Ambiguous responses recover by GET with bounded
observation; they never resubmit an unknown execution. Terminal execution keeps
GET readback active until automatic evaluation arrives. Legacy reads/serialization
omit all new automation fields. Existing Human paths and source-change records
remain separate; source replacement itself does not start a Run. Only the
separately configured read-only execution command can authorize its new successor.

G1 resource page group has authenticated scope-correct catalog/Skill/MCP version
and usage views behind VITE_RESOURCE_DIRECTORY_ENABLED; legacy development forms
remain in their previous build mode. The new views show only exact readable
versions, scope/subject-bound keyset pagination, inline configuration and readable
actual execution links. No default tenant/header impersonation. Create/import/
edit/lifecycle management and full page/state parity remain OPEN, not hidden by
these read views. New profile tests are separately runnable with
npm run test:resource-management / make resource-management-e2e; legacy profile
assertions are not skipped or rewritten to fit the new UI.
