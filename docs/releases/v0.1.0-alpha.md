# v0.1.0-alpha release notes

These notes are prepared for the first public prerelease of the Enterprise
Agent Platform. The release is an Alpha engineering milestone for its
Kubernetes-native Agent Control Plane. It is not production-ready.

## Release contract

The public release identity is the immutable annotated Git tag
`v0.1.0-alpha` and the exact commit it identifies. The GitHub prerelease and its
automatically generated source archives are the distributed artifacts.

No container images, Python packages, Helm charts, CLI binaries, standalone
installers, checksums, signatures, or SBOMs are published for this release.
The versions exposed by individual components, the `agentos.io/v1alpha1` API
version, frontend package metadata, and local development image tags are not
the public release identity.

## What is included

- Kubernetes `Agent`, `Task`, and `Workflow` custom resources.
- Operator reconciliation for agent workloads and task execution.
- Workflow DAG scheduling with dependency propagation, retries, independent
  branches, failure handling, and dependency skips.
- A replaceable Python agent runtime with deterministic mock and
  OpenAI-compatible model-provider adapters.
- A read-only Console for inspecting current Workflow and Task state from
  Kubernetes.
- An ownership-safe [Quick Start](../../README.md#quick-start) and a
  [Golden Engineering Demo](../../examples/golden-engineering-demo/README.md).

For the precise current boundary, see
[Current Implementation](../engineering/CURRENT_IMPLEMENTATION.md). Product,
architecture, and roadmap documents also describe planned or conceptual work;
those descriptions are not release claims.

## Install and verify

Use a source archive provided automatically by GitHub or check out the exact
`v0.1.0-alpha` tag. Follow the [Quick Start](../../README.md#quick-start) for the
shortest local journey, or the
[detailed local Kubernetes guide](../../manifests/README.md) for manual steps.

Both paths build operator and runtime images locally. They require Docker,
kind, kubectl, and outbound access to the external registries and Python
artifacts documented by those guides. Local image tags are mutable development
handles, not durable release artifacts. Record the resulting image IDs when an
exact local execution identity is required.

## Reproducibility and qualification

The tag and commit make the released source tree reproducible. Python
dependencies are locked, but container base-image references are not pinned by
digest and external artifacts remain outside repository control. The project
therefore claims source traceability and rebuildability, not byte-for-byte
binary or container-image reproducibility.

Release qualification is bounded to:

- macOS ARM64 local development using Docker Desktop and kind;
- Ubuntu 24.04 Linux AMD64 on a native/cloud host using Docker and kind.

This evidence does not establish compatibility with other operating systems,
architectures, Kubernetes distributions, or production environments.

## Compatibility and upgrade boundary

The Kubernetes API remains `agentos.io/v1alpha1`. Alpha APIs, status behavior,
manifests, and component internals may change in later releases. No backward
compatibility, data migration, or in-place upgrade path is guaranteed. Preserve
declarative resources and review future release notes before replacing an Alpha
installation.

## Known limitations

- The release is source-only and requires a local container build.
- It provides no production support, availability, security, performance,
  compatibility, or remediation SLA.
- The Console is read-only and has no authentication, authorization,
  multi-tenancy, durable history, distributed tracing, or cost governance.
- Enterprise governance, policy, audit, and secret-management capabilities are
  not implemented.
- Accepted ADR-0003, ADR-0004, and ADR-0005 have documented implementation
  drift; see the [ADR index](../../adr/README.md).
- The mock provider is intended for deterministic engineering validation, not
  a production model workload.

Report suspected vulnerabilities privately by following
[SECURITY.md](../../SECURITY.md). Use the
[contributor guide](../../CONTRIBUTING.md) for bugs, feature requests,
questions, and changes.

## Publication checklist

### Before publication

- [ ] Confirm the candidate is the approved, synchronized `main` commit and the
  working tree is clean.
- [ ] Confirm `v0.1.0-alpha` does not already exist locally, remotely, or as a
  GitHub Release.
- [ ] Review this file and [CHANGELOG.md](../../CHANGELOG.md) against the final
  candidate diff.
- [ ] Run `make check`, frontend locked install/lint/build validation, Markdown
  link validation, and all release-candidate CI checks.
- [ ] Reconfirm repository security/hygiene status, the Quick Start, Golden
  Engineering Demo, and qualified Linux evidence remain applicable to the
  candidate commit.
- [ ] Obtain the required human approval for publication.

### Publication

- [ ] Record the exact candidate commit SHA.
- [ ] Create the annotated, unsigned tag `v0.1.0-alpha` at that exact commit;
  never move or reuse it.
- [ ] Push only that tag after verifying its target.
- [ ] Create a GitHub Release titled
  `v0.1.0-alpha — Agent Control Plane Core`, target the verified tag, mark it as
  a prerelease, and use this file as the curated notes without generated notes.
- [ ] Attach no additional artifacts; retain GitHub's automatic source archives.

### After publication

- [ ] Verify the tag, commit, prerelease marker, notes, and source archives from
  GitHub.
- [ ] Extract an automatic source archive and confirm its repository layout and
  documentation entry points.
- [ ] Run a bounded source-based Quick Start smoke test and record the platform,
  source commit, local image IDs, and result.
- [ ] Confirm the release page links users to the security and contribution
  policies.

Tag creation, pushing, and GitHub Release publication are intentionally deferred
to the separately authorized release-publication task.
