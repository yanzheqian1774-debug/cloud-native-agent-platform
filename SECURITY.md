# Security Policy

## Supported versions

This project is under active development toward `v0.1.0-alpha`. No release or
version tag has been published, so there are currently no supported releases.
The current source tree is pre-release software and does not carry production
support or security guarantees.

This policy will be updated when the project publishes supported releases.

## Reporting a vulnerability

Report suspected vulnerabilities privately through GitHub Private
Vulnerability Reporting:

1. Open this repository on GitHub.
2. Select the **Security** tab.
3. Select **Report a vulnerability** and complete the private report form.

Do not open a public issue, discussion, or pull request for a suspected
vulnerability. Please avoid public disclosure until the maintainers have had
an opportunity to investigate and coordinate any remediation and disclosure.

Include as much of the following information as is available:

- the affected component and version, tag, or commit;
- the environment and configuration used;
- steps to reproduce the issue;
- a proof of concept, logs, or other supporting evidence, with secrets and
  personal data removed;
- the potential impact and attack scenario;
- any known mitigations or suggested remediation; and
- whether the issue has been disclosed elsewhere.

GitHub's private report will be used to coordinate follow-up. The project does
not currently promise response or remediation timelines.

This reporting policy does not imply that planned enterprise security
capabilities, including authentication, authorization, multi-tenancy, RBAC,
policy enforcement, secret management, or auditing, are implemented.
